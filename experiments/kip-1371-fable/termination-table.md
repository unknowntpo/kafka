### 三個時間界限

- **`closeTimer`**（步 2）：步 3 的 sync autocommit、步 6 的 leave、步 7 的 async commit 等待、步 8 的 network thread join／`sendUnsentRequests` 全部從同一個 timer 扣。零 timeout 時步 3、6、7 立即逾時，步 8 的 `sendUnsentRequests` 至少跑一次 `poll(0)`。
- **`request.timeout.ms`**：每個 `UnsentRequest` 入列時 `setTimer`（`I/NetworkClientDelegate.java:324-345`、`:427`），`trySend` 逾時 → `onFailure(TimeoutException)`（`:213-219`）；已送出者交給 `NetworkClient` in-flight 逾時。但 close 後 `NetworkClient.close()` 不觸發這個逾時。
- **event deadline**：`CompletableApplicationEvent.deadlineMs`，由 reaper 在每輪 `runOnce`（`I/ConsumerNetworkThread.java:239`、`:285`）與 cleanup(c) 執行。`AsyncPollEvent` 不是 completable，沒有 reaper 終止。

## 4. 本輪未改動 production code 的理由

#5 是唯一「manager 層 future 沒有終止者」的列。它的 app 端觀察面（`CheckAndUpdatePositionsEvent`／`FetchCommittedOffsetsEvent`）都由 reaper 終止，`AsyncPollEvent` 則沒有人等，因此沒有可 hang 的呼叫者。依規則（測試證明 pending 工作沒有終止者才改），這裡只以 characterization test 釘住現況並列入 §3。
